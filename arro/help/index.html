Help

Install #

Download the package or archive for your system from the latest release. Every file has a .sha256 file next to it.

You need a JDK 25 or newer for the language server, for example Eclipse Temurin 25. Your projects can still build on their own JDK, from 8 to 25. The Java language server and the debugger are already in the download.

Windows 11, x86-64

  1. Download arro-0.1.32-windows-x86_64.zip.
  2. Unpack it into a folder you can write to, so Arro can update itself there later.
  3. Run arro.exe and open a folder with a Maven or Gradle project.

run-arro.cmd in the same folder finds the JDK and the bundled tools for you; starting arro.exe directly works too.

Linux, x86-64

Arro needs glibc 2.35 or newer: Ubuntu 22.04, Debian 12, Fedora 36 or a later release.

Debian and Ubuntu: the package

  1. Download arro_0.1.32_amd64.deb.
  2. Install it from the download folder: 
    sudo apt install ./arro_0.1.32_amd64.deb
  3. Start Arro from the application menu, or run arro.

The package puts Arro in /opt/arro, adds arro to the path and a shortcut to the application menu. A newer version installs the same way. Arro cannot update a package installation by itself, so its update notice opens the release page.

Other distributions: the archive

  1. Unpack arro-0.1.32-linux-x86_64.tar.gz, for example into ~/opt.
  2. Run ./arro from that folder.
  3. For a shortcut in the application menu, run ./install.sh and answer its question. It writes only to ~/.local/share of your user; nothing is installed automatically.

The window needs libfontconfig, libwayland, libx11, libxcb and libxkbcommon at run time. README.txt in the archive lists the JDK search paths and the servers it ships.

macOS, Apple silicon

  1. Open arro-0.1.32-macos-aarch64.dmg and drag Arro into Applications. The .zip of the same bundle works too; it is what the built-in updater uses.
  2. The build is signed ad hoc, not notarized, so Gatekeeper stops the first start. Control-click Arro.app, choose Open and confirm, or run: 
    xattr -dr com.apple.quarantine /Applications/Arro.app
  3. Open Arro.app. To open a project folder directly: 
    open Arro.app --args /work/shop

The published build is for Apple silicon. README.txt inside the bundle explains the JDK search and where Arro keeps its files.

First steps #

  1. Open a project. Open a folder with a Maven or Gradle project. Arro imports it and starts the Eclipse JDT Language Server, which it watches and restarts for you.
  2. Or start a new one. File → New → Project creates a Java project with Maven or Gradle (Groovy or Kotlin DSL), a Spring Boot project from Spring Initializr with a searchable dependency list, or an empty project, with an optional Git repository.
  3. Find anything. Press Shift twice for Search Everywhere, Ctrl+N for a class, and Alt+Enter on anything underlined for fixes.
  4. Run it. Click the run mark in the gutter next to main or a test, or use a run configuration.

Coming from IntelliJ IDEA

The shortcuts, menus and tool windows follow IntelliJ IDEA. A project with .idea/codeStyles/Project.xml keeps its style: indents, tabs and the right margin in the editor, and the Java formatter and import order through the language server. .editorconfig still wins, and Settings → Editor → Code Style shows which file is used.

File → Manage IDE Settings exports and imports Arro’s settings, keymap and templates as one zip, without passwords and tokens.

Features by area #

Editor

Semantic highlighting, parameter name hints, folding, multiple carets, live and postfix templates, a scroll bar with problem marks, sticky lines, bookmarks, split editors, Compare with Clipboard, and actions on save that reformat and optimize imports. A Markdown preview shows images.

Code intelligence

Completion with auto-import, quick fixes on Alt+Enter, Find Usages, call and type hierarchy and class diagrams. Refactorings: rename, extract, inline, change signature and safe delete, all listed at the caret by Refactor This. Structural Search and Replace, reformat, optimize imports and Create Test.

Settings → Editor → Inspections lists the checks of Arro and the Java compiler; each can be turned on or off and given a level, saved in the project. Alt+Enter on a warning can suppress it for the statement, method or class.

Run, test, debug

  • Run configurations with Before launch steps, Compound configurations, and an .env file per configuration.
  • A test tree with rerun of failures, tests rerun after each save, and a history of the last runs.
  • The debugger: breakpoints, stepping, evaluation, hot swap, values inline in the editor, remote JVM attach, marked objects, folded library frames, inline watches and virtual threads.
  • Analyze Stack Trace turns a pasted trace or thread dump into clickable frames; Dump Threads reads a running JVM.
  • The Services window shows every Spring Boot app and main class with its state and port.

Spring

  • Completion, hover and checks for application.properties and .yml, from the configuration metadata on your class path.
  • A Beans window with injection gutter marks, and an Endpoints window with every HTTP handler.
  • Spring Data JPA query methods and JPQL in @Query, completed and checked against your entities.
  • Message bundles linked to getMessage, validation messages and Thymeleaf #{…}.
  • A running Spring Boot app gets an Actuator tab with live Health, Beans, Mappings and Environment.

Tools in the window

  • A database console for JDBC sources with a schema tree; Ctrl+Enter runs a statement.
  • An HTTP client for .http files that turns pasted cURL into requests and back.
  • A profiler on Java Flight Recorder: CPU, allocations and a thread timeline, for apps, tests and Maven or Gradle tasks.
  • A JShell console on the class path of a module, a dependency analyzer for conflicts and duplicates, and newer dependency versions marked in pom.xml and Gradle files.
  • A table editor for .properties bundles of all locales, library sources on demand, and Docker services.

Git

Commit, diff, log, branches with merge, rebase and compare, shelf and stash, conflict resolution, history of a selection or a method, submodules and local history.

Terminal

Sessions as tabs with a shell picker (PowerShell, cmd, Git Bash and WSL on Windows; your $SHELL, bash, zsh or fish elsewhere), Split Right and Split Down, search through the whole scrollback, and Ctrl+click on URLs, file paths with a line, compiler output and Java stack frames. Tabs come back after a restart.

Settings and appearance

Dark and light themes, a configurable keymap, and View → Appearance with Full Screen, Distraction Free, Zen and Presentation modes, toggles for the toolbar, status bar, breadcrumbs, line numbers and more, and Zoom IDE.

Updates #

Arro checks for updates once a day and can update itself; the check can be turned off in Settings. The updater takes the archive of the running system: the zip on Windows, the tar.gz on Linux, the whole Arro.app bundle on macOS.

Keep the folder you unpacked Arro into writable, otherwise the update stops with a message. A .deb installation is updated by installing the new package; its update notice opens the release page.

Limitations #

Arro is an early preview. Expect rough edges, missing features and breaking changes between versions.

  • Linux and macOS are early previews: they build and pass the tests, but fewer people use them than the Windows build.
  • The macOS build is not notarized, so the first start needs the step in the install guide.
  • Linux is built for x86-64 only, and the published macOS build is for Apple silicon.
  • There is no .rpm, Flatpak or Homebrew package yet. They are on the roadmap.
  • On Linux the terminal uses the system pseudo terminal.

Build from source #

The Rust toolchain is pinned in rust-toolchain.toml of the repository.

cargo build --release -p ide
cargo run -p xtask -- dist --out <folder>
cargo run -p xtask -- dist --target linux --out <folder> --zip
cargo run -p xtask -- dist --target macos --out <folder> --zip

Build --target linux and --target macos on their own system; the archives they write are the ones the updater looks for. cargo run -p xtask -- ci runs formatting, lints, tests, licence and architecture checks.

Getting help #

Found a problem? Open an issue on GitHub; bug reports are very welcome. Arro is free; if it saves you time, you can support it through GitHub Sponsors.
